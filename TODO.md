# GSR Project To-Dos

1. **Dedupe Results (High Redundancy):** Implement a post-processing mechanism to deduplicate results generated by the subagent approach. Currently, multiple specialized agents (like Architecture and Logic) often report the exact same localized root causes on the identical AST node, creating unnecessary review noise.
   - *Proposal:* Build a post-orchestration Synthesizer / Deduplication Agent that consumes the entire array of subagent outputs, merges identical/overlapping line comments into cohesive reviews, and outputs the final clean array.
2. **Improve Prompts:** Refine and improve the specific prompts utilized by the various subagents.
3. **Review Granularity:** Evaluate whether it is better to stick with the file-by-file review approach, or process the entire pull request context collectively across the board.
4. **Optimize Subagent Concurrency:** Reduce the sheer number of independent subagent tasks generated (currently ~200 tasks for large PRs) by batching files or analyzing the aggregated diff as a whole instead of evaluating every file with every subagent independently.
5. **Evaluation UI:** Build a UI as part of the ADK frontend to visualize and show the results of the evaluation comparisons.
6. **Evals Dataset:** Create a standardized evaluation dataset (a robust set of diverse Pull Requests) to run comparisons against automatically.
7. **Context Optimization:** Better understand how context is shared between the agents and optimize the flow to reduce overhead or improve reasoning.
8. **Evals Harness Verbosity:** Improve and streamline the verbosity of the evaluation harness outputs and logs to make debugging or monitoring easier.
9. **Code Changes vs LLM Variance:** Focus the evaluation harness strictly on actual programmatic code changes made in GSR, reducing noise triggered by general differences in random LLM variance across baseline comparisons.
10. **Model Upgrades:** Migrate the primary subagent execution to use Gemini 3.1 Pro and implement graceful fallback logic to standard 3.1 Flash (or equivalents) in the event of API quota limits or downtime.
    - *Proposal:* Add a configuration flag to run the Triage Agent router using `gemini-2.5-pro` (defaulted to off) instead of `gemini-2.5-flash` to evaluate if the larger model performs better zero-shot agent routing.
11. **Payload Batching:** Implement dynamic file chunking logic in the orchestrator to prevent crashing the Gemini API with payloads exceeding the 10MB limit.
12. **Context Sharing Architectures:** Explore and implement techniques (like Rolling Summarization or global AST skeletons) to maintain context awareness across separated batches for massive 1,000+ file monolithic PRs.
13. **Persistent Review History:** Make the code review tab persistent so it shows the last code review result and keeps a running history of previous PR analyses.
14. **Metrics & Usage Dashboard:** Implement programmatic metric tracking and a dedicated usage dashboard for monitoring system performance over time.
15. **AST Context Pruning:** Implement aggressive context window pruning via Abstract Syntax Trees or enhanced filtering to reduce the 13% input token overhead observed in the local evaluation.
16. **Automated Evals/Fix Loop:** Build an automated execution loop that routinely runs the Evaluation Harness and forces AI agents to iterate on prompt refinement based on regressions detected in the baseline.
17. **Resolve P0 Coverage Bug (File Skipping):** 
    - *Problem:* Subagents stubbornly skip certain generalized files (e.g., `eslint.config.js`) during the Discovery phase despite strict JSON Schema retry loops. This occurs because highly specialized roles (e.g., "CICD Agent", "Performance Agent") cause the LLM to aggressively filter out out-of-scope files.
    - *Solution:* Soften or remove the strict agent-specialty role constraints during the Pass 1 Discovery Phase, or create a generalized "Coverage Agent" that guarantees every file is scanned fundamentally before passing to specialized Mentors.
18. **Configurable Token Limits:** Introduce application-level configurable caps (`MAX_INPUT_TOKENS`, `MAX_OUTPUT_TOKENS`) for the code review process to better manage API costs and prevent runaway token consumption per PR analysis.
19. **Resolve Testing Subagent Regression:**
    - *Problem:* In the transition to the Two-Pass architecture, the `Testing` subagent lost strategic context sensitivity. It now occasionally recommends brittle, lower-quality unit tests instead of superior integration tests (observed in PR #1 evaluation).
    - *Solution:* Perform a root cause analysis on the `Testing` subagent's prompt constraints. Restore its core ability to differentiate between testing paradigms (unit, integration, E2E) and ensure it evaluates architectural suitability prior to generating test stubs.
20. **Optimize Evaluation Output Verbosity:**
    - *Problem:* Evaluation harness runs currently generate massive walls of text, inflating our *Output Token* consumption and reducing readability.
    - *Solution:* Constrain the LLM Prompts within `evaluate.ts` to enforce strictly concise wording, summarize findings tersely, and aggressively reduce unnecessary prose to save downstream token costs.
32. **Implement Post-Execution Triage Architecture:** Pivot the current "Pre-Filter" Triage routing (which drops context) into a "Post-Execution" Deduplicator that merges overlapping findings from all specialist agents.
32. **~~Implement Vertex AI Context Caching~~ Gemini API Context Caching:** Cache the static system prompts and agent personas using the Gemini API's context caching (implemented in `agent.ts` via `USE_CONTEXT_CACHING`, independent of Vertex/ADC) to achieve a 90% reduction in input token costs.
33. **[P0 Blocker] Fix Deduplicator Formatting Regression:** Investigate and fix the root cause of the catastrophic consolidation failure in `deduplicator.ts` where overlapping findings are occasionally merged into an unformatted, unreadable "wall of text" resulting in malformed UI output.
34. **Thinking Budget Config:** Add a configuration mechanism (e.g., `GEMINI_THINKING_BUDGET`) to optionally supply a token "thinking budget" to the Gemini SDK (`thinkingConfig`) to enable and scale advanced reasoning capabilities during the review process.
35. **Basic Agent Catch-All:** Have the basic agent run as a catch-all as part of the agent swarm to catch broad logic bugs that specialized agents might miss.

37. **Explore Advisor Strategy:** Evaluate and potentially implement the Advisor Strategy to reduce noise and cost in the multi-agent review flow (see [advisor-strategy-options.md](advisor-strategy-options.md)).
38. **Managerial Feedback Agent:** Add a sub-agent to give managerial feedback on the PR (high-level impact, risk assessment, adherence to guidelines).
39. **Verify the image-generation and Gemini 3.8 price rows against Google's official pricing page:** every rate added to `adk/backend/src/usage.ts`'s `PRICE_TABLE` for `gemini-3.8-flash`, the three Gemini image models, and the three Imagen 4 models came from secondary sources — `ai.google.dev`, `openrouter.ai` and the vendor blogs are all blocked by the agent egress proxy, so no primary source was ever read. The figures are internally consistent (each published per-image price falls out of the token rate, and 3 Pro Image's $0.0011-per-input-image confirms its $2.00/1M input rate), but consistency across secondary sources is not verification. See "Known pricing gaps" in [usage_analytics_reference.md](usage_analytics_reference.md).
40. **Diary the introductory-rate expiry (2026-12-31):** `gemini-3.7-flash` and `gemini-3.8-flash` are both priced at their introductory $0.75/$3.75 and double to $1.50/$7.50 on 2027-01-01. Nothing in the code or CI notices the rollover — every review after that date silently under-reports by half until someone edits the table.
41. **Price text and image output separately for the image models:** `computeCostUsd` applies one `output` rate to `candidatesTokenCount` as a whole, and `PRICE_TABLE` stores the *image* rate for the image models. A response mixing prose and images therefore over-bills its text tokens (3 Pro Image: $12/1M text vs $120/1M image; 3.1 Flash Lite Image: $1.50/1M vs $30/1M). The fix is to plumb `usageMetadata`'s per-modality token breakdown through `GenerateContentLikeResponse` and split the rate — harmless while nothing here generates images, a real error the moment something does.
42. **Settle the thinking-token billing convention across the projects feeding the usage dashboard:** GSR's `computeCostUsd` deliberately excludes `thinkingTokens` (the output rate is documented as already including them, so adding them risks double-billing), while cat-chat's `docs/R2-MIGRATION-DESIGN.md` §8a.2 specifies the opposite — thinking tokens billed at the output rate — and sound-profile-builder's Go reporter is that design's model. Since `ingestUsageRecords` stores each client's `costUsd` verbatim, the same call costs different amounts depending on which project reported it, and `totalCostUsd` blends both. Pick one convention and align the tables before more reporters land.
43. **Sync the sibling price tables:** the sibling `job_tracker` project's `internal/scoring/pricing.go` still lacks `gemini-3.8-flash` and every image model. `tools/eval/usage.ts`'s copy carries only `gemini-2.5-pro` by design (its `llm-comparator*.ts` hardcode that model), so it needs an entry only if the judge model ever changes.
44. **Surface image usage on the dashboard:** `imageCount` is recorded per call but deliberately not aggregated — `UsageBucket`/`Rollup` were left untouched so no rollup schema-version bump was needed and `usage-report.js`'s hand-copied `aggregate()` wouldn't drift. Image spend still totals correctly through `costUsd`; add an images column to the buckets (and bump `SCHEMA_VERSION`) if per-image volume ever needs its own line.
